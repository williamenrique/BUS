🗺️ Flujograma del Proceso de Requisición y Despacho
El proceso se divide en la Generación de la Requisición, la Gestión de Compras/Inventario, y el Despacho desde Almacén.
1. Generación de la Requisición (Jefe de Patio)
1.	Inicio: La Unidad/Operador reporta una falla o necesidad de artículo.
2.	Verificación: El Chequeador confirma la falla/necesidad y notifica al Mecánico y Jefe de Patio.
3.	Creación de la Requisición: El Jefe de Patio crea una Orden de Requisición con los detalles y los artículos requeridos.
________________________________________
2. Gestión de Compras/Inventario
1.	Recepción: El departamento de Compras recibe la Orden de Requisición.
2.	Verificación de Stock: Compras verifica si el artículo/repuesto está disponible en el inventario.
o	Si hay stock (Tipo: Servicio/Reparación con stock): Se convierte la Requisición en una Orden de Despacho interna y se envía a Almacén.
o	Si no hay stock (Tipo: Compra): Compras inicia el proceso de adquisición (que puede terminar en una compra pendiente, ligada a tu tabla table_compras_pendientes). Una vez adquirido, se convierte en una Orden de Despacho y se envía a Almacén.
________________________________________
3. Despacho y Cierre (Almacén)
1.	Recepción de Orden: Almacén recibe la Orden de Despacho (digital).
2.	Despacho Físico: Almacén prepara y entrega el artículo físicamente.
3.	Confirmación y Descuento: Al recibir la confirmación del despacho físico, Almacén marca la Orden de Despacho como Despachada y procede a restar los ítems del inventario (table_alm_relacion_producto).
________________________________________

🔄 Flujo de Datos con la Tabla Existente
El nuevo flujo garantizaría que todo el proceso de Mantenimiento/Flota quede registrado en las nuevas tablas, pero la acción final de inventario siempre se centralice en las tablas de Almacén.
1. Generación de la Requisición
•	El Jefe de Patio crea la Requisición (table_mto_requisicion).
•	Los artículos se detallan en table_mto_detalle_req.
•	La requisición tiene status_requisicion = 1 (Pendiente).
2. Conversión a Orden de Despacho (Compras)
•	Cuando Compras aprueba y confirma el stock (o la adquisición), se ejecuta un INSERT en la tabla table_alm_despacho.
•	Campos clave para el INSERT:
o	id_flota, operador, mecanico, etc., se toman de la Requisición.
o	origen_despacho se establece como 'Requisicion'.
o	id_requisicion_origen se establece al ID de la requisición.
•	Artículos: Se insertan los detalles de los productos en table_alm_relacion_despacho, enlazados al nuevo id_despacho generado.
•	Enlace de Historial: (Opcional, si no se usa id_requisicion_origen): Se usa la tabla de enlace table_mto_req_despacho para relacionar id_requisicion con el nuevo id_despacho.
3. Cierre del Despacho (Almacén)
•	Almacén encuentra la orden en table_alm_despacho.
•	Si el origen_despacho es 'Requisicion', sabe que debe verificar el id_requisicion_origen para ver el detalle de la solicitud inicial.
•	Al despachar el material, se actualiza el status_despacho y se resta el inventario de table_alm_relacion_producto, usando el mismo proceso que ya tienes en producción.
✅ Ventajas de esta Opción
•	Integración: Reutilizas la lógica de despacho y el proceso de descuento de inventario ya existentes, minimizando el cambio en el código actual.
•	Historial Centralizado: Todos los despachos (sea por Mantenimiento/Requisición o por otro motivo) quedan en una sola tabla (table_alm_despacho).
•	Diferenciación Clara: Los nuevos campos (origen_despacho y id_requisicion_origen) permiten filtrar reportes y distinguir la fuente de cada orden de forma rápida.

🛠️ SQL para la Creación de las Nuevas Tablas
SQL
-- TABLA: table_mto_requisicion (Orden de Requisición generada por Jefe de Patio)
DROP TABLE IF EXISTS `table_mto_requisicion`;
CREATE TABLE `table_mto_requisicion` (
  `id_requisicion` INT(11) NOT NULL,
  `fecha_requisicion` VARCHAR(12) DEFAULT NULL,
  `id_flota` INT(11) NOT NULL,
  `operador_cedula` VARCHAR(15) DEFAULT NULL,
  `chequeador_cedula` VARCHAR(15) DEFAULT NULL,
  `mecanico_cedula` VARCHAR(15) DEFAULT NULL,
  `jefe_patio_id` INT(11) NOT NULL,
  `tipo_orden` ENUM('Servicio', 'Compra', 'Reparacion') NOT NULL,
  `diagnostico` MEDIUMTEXT DEFAULT NULL,
  `status_requisicion` INT(11) NOT NULL COMMENT '1: Pendiente, 2: Aprobada/En Proceso, 3: Rechazada, 4: Convertida a Despacho/Compra'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_spanish_ci;

-- TABLA: table_mto_detalle_req (Artículos solicitados en la Requisición)
DROP TABLE IF EXISTS `table_mto_detalle_req`;
CREATE TABLE `table_mto_detalle_req` (
  `id_detalle_req` INT(11) NOT NULL,
  `id_requisicion` INT(11) NOT NULL,
  `id_producto` INT(11) NOT NULL,
  `cant_solicitada` FLOAT DEFAULT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_spanish_ci;

-- TABLA: table_mto_req_despacho (Enlace entre Requisición y Despacho)
DROP TABLE IF EXISTS `table_mto_req_despacho`;
CREATE TABLE `table_mto_req_despacho` (
  `id_enlace` INT(11) NOT NULL,
  `id_requisicion` INT(11) NOT NULL,
  `id_despacho` INT(11) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_spanish_ci;

-- TABLA: table_mto_status_req (Historial de Estatus de la Requisición)
DROP TABLE IF EXISTS `table_mto_status_req`;
CREATE TABLE `table_mto_status_req` (
  `id_status_req` INT(11) NOT NULL,
  `id_requisicion` INT(11) NOT NULL,
  `status_anterior` INT(11) DEFAULT NULL,
  `status_nuevo` INT(11) DEFAULT NULL,
  `observacion` MEDIUMTEXT DEFAULT NULL,
  `user_id` INT(11) NOT NULL,
  `fecha_cambio` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_spanish_ci;
